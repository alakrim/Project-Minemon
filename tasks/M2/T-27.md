# T-27 — minemon_growth: exp, levels, move learning, bond, evolution (incl. stones and the Link Cable)
ID / milestone / wave / risk: T-27 / M2 / wave 1 / high (player progression; party data writes)

## Goal and why
The grind has to pay off. Your partner gains exp from every defeat, levels up, learns moves and grows bond. Then, in a dark cinematic, it **evolves**. See D-030.

## Read
CLAUDE.md, docs/CONVENTIONS.md, docs/PLAN.md (the M1 contract), docs/DECISIONS.md D-026..D-030, mods/minemon/minemon_core/{formulas.lua, instance.lua, data.lua, data/species.json (learnset, evolutions, growth_rate, base_exp), data/items.json}, mods/minemon/minemon_party/{init.lua, party_logic.lua, ui.lua}, mods/minemon/minemon_creatures/{runtime.lua, init.lua} (read only).

## Interfaces / invariants
- **New mod `minemon_growth`.** Depends on minemon_core, minemon_creatures and minemon_party. Pure logic goes in `growth_logic.lua` (no `core`).
- **Event input:** `creature_defeated(victim_le, attacker_obj)`. T-26 adds the fire call in parallel; your tests fire the event themselves.
  - Find the beneficiary: if `attacker_obj` is a player, use that player's active creature; if it is an owned creature, use the creature itself (its owner's party member). Otherwise there is no exp.
  - Exp = `minemon.formulas.exp_gain(victim_species.base_exp, victim_inst.level, beneficiary_bond)`.
- **Updating a party member:** use `minemon.party.get(player)`, change the member by uid, then `minemon.party.set(player, list)`.
  - If the member is the active creature, update the live entity's `_mm` the same way: read how party write-back works, so the next write-back does not overwrite your change, and change both.
  - If it cleanly avoids races, add a small helper `minemon.party.update_member(player, uid, fn)` in minemon_party/init.lua (that one function only).
- **Levelling:** the level comes from `level_for_exp(exp, species.growth_rate)`, capped at 100; several levels at once are allowed.
  - On each level: recompute the stats with `minemon.instance.stats` and keep the HP **fraction** (new_hp = ceil(frac × new_max)).
  - Update the nametag and the party HUD through existing functions if available.
  - Chat line, in green: "<Name> grew to Lv N!". Show a sparkle particle burst on the entity if it is out.
- **Move learning:** for each learnset entry with level in (old, new]:
  - fewer than 4 moves, not already known: learn it with full pp ("<Name> learned <Move>!");
  - 4 moves known: open a formspec "<Name> wants to learn <Move> (type, power). Forget a move?" with 4 buttons (move name, type, pp) and "Don't learn". Queue several prompts.
  - If the player closes the formspec, it counts as "Don't learn".
- **Bond** (0..255):
  - +3 per level-up when bond < 100, else +2;
  - +1 per 120 s of being the active creature (count in a globalstep);
  - −5 on faint (listen to `creature_fainted`);
  - capture sets 70 (T-26).

  Show bond in the party formspec row as hearts (♥ = bond/51, rounded) if ui.lua offers a hook; otherwise use `/party`.
- **Evolution check** with `growth_logic.can_evolve(inst, species, ctx)`. ctx = `{is_night, used_item, link_cable, inventory_has(item)}`. Every key in `conditions` must hold:
  - min_level, item, min_bond, time_of_day (VoxeLibre: day = timeofday 0.25..0.75), stat_relation (attack_gt_defense / attack_lt_defense / attack_eq_defense on current stats), trade, held_item.
  - It runs after a level-up (level-only and level+other conditions) and when an item is used.
- **Evolution items:** register `minemon:<id>` for every items.json entry of kind `evo_stone`, `held_evo` or `evo`, with generated icons via tools/gen_icons.py (simple gem, coin and cable shapes; our art). Use on_secondary_use and on_place:
  - target the player's active creature (else the lead);
  - if a conditions set matches with this item (stone → `item`; Link Cable → `trade`, plus `held_item` checked in the inventory), consume the item(s) and evolve;
  - otherwise say "It had no effect.".
- **Link Cable price:** set it to 2100 in items.json, so the T-28 shop can sell it (the only data edit allowed).
- **Evolution cinematic:**
  - A formspec "What? <Name> is evolving!" with a "Stop it!" button, open for 6 s. If stopped: "<Name> stopped evolving." (it will ask again at the next level-up).
  - If the creature is out, the entity is frozen. Dark purple and black particles spiral in and the glow flickers (`set_properties` glow toggling); use a deep VoxeLibre sound such as the portal or wither sounds, if present.
  - Then do the evolution: recall if active, change `species_id` keeping uid, nickname, ivs, exp, bond, moves and status, recompute the stats keeping the HP fraction, `party.set`, then `send_out` the same index again if it was active.
  - Chat line, in gold: "<Old> evolved into <New>!". Then check the new species' learnset at the current level and learn the moves as above.
  - Fire the `creature_evolved(player, inst, old_species_id)` event.
- **Player-facing:** `/exp` shows the active creature's level, exp and next-level exp. `/givexp <n>` (privilege give) grants exp to the active creature or the lead.
