# T-23b — Combat fixes from the second verification (attempt 2 of T-23)
ID / milestone / wave / risk: T-23b / M1 / wave 3 / high

## Goal and why
The T-23 verifier (tasks/M1/T-23.verdict.md) found a server crash, a state bug that survives reloads, and a facing bug that makes melee whiff (and the combat test flaky). Fix them with product fixes, not test workarounds.

## Read
CLAUDE.md, docs/CONVENTIONS.md, tasks/M1/T-23.md, tasks/M1/T-23.verdict.md, mods/minemon/minemon_combat/*.lua, mods/minemon/minemon_creatures/runtime.lua (register_brain API: read only), tests/integration/combat/init.lua.

## Fixes
1. **Crash:** `use_move` must validate the target. A non-creature, non-player target returns `false, "bad target"`. For player targets, never call `formulas.damage` with a nil view: players take the player damage path (as specified in T-23), and status_cloud and aura moves skip players, or apply only the cosmetic effect. Nil-check every `view_of` use in archetypes.lua. Every `core.after` callback is wrapped in pcall and logs on error, so the server can never crash from a combat callback.
2. **Facing:** at cast start and again at execution, the user turns to face the target (`set_yaw` toward the target; for mcl mobs also set `self.object:set_yaw` and stop wander turning for the cast: `self.state = "attack"` or the equivalent; check mcl movement.lua:653-674). The melee check uses the facing at execution after turning, so a valid melee in range never whiffs because of idle turning.
3. **Status persistence:** register a brain `"status_restore"` via `minemon.creatures.register_brain` (first-come order is fine). On an entity's first tick after activation, if `_mm.status` is not "none" and the entity is not in the status registry, either re-register it with a fresh duration (sleep or freeze: 3 s, burn, poison or paralysis: 12 s) and re-apply the speed mirror, or clear it. Also store the original walk and run velocities in persistent fields `_mm_base_walk` and `_mm_base_run` the first time a speed mirror is applied, and always restore from those.
4. **Move warnings list:** write `docs/moves_unsupported.md` (generated by the validation script, committed) listing each move whose effect is not implemented, with its reason (grouped). Point to it from tasks/M1/T-23.report.md.
5. **Test:** remove the accuracy-stage workaround in tests/integration/combat check (c), if it is no longer needed. Add checks:
   - **(h)** use_move on a non-creature entity returns false and the server keeps running;
   - **(i)** freeze a creature, round-trip its staticdata through remove plus `core.add_entity`, wait 1 s, and confirm it is either re-registered or has fully restored speed and status none;
   - **(j)** a melee attack while the user is rotated 180° away from the target still hits (it turns first).
