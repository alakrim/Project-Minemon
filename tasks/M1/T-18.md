# T-18 — Procedural stand-in creature models and textures (our own art)
ID / milestone / wave / risk: T-18 / M1 / wave 1 / medium (visual quality)

## Goal and why
Until the owner supplies Pokémon visuals (D-014), every species needs a readable, charming-but-creepy blocky stand-in that fits VoxeLibre's look: one model per body plan, tinted by type, with eyes. This is our own procedural art; never imitate any Pokémon design.

## Read
CLAUDE.md, docs/CONVENTIONS.md, docs/research/S-11-creatures-pipeline.md (glTF facts for Luanti), docs/research/S-12-voxelibre-mobs-api.md (§1 Visuals and Animation keys), `.tools/luanti/doc/lua_api.md` (the glTF section). Look at VoxeLibre mob models for style and scale (`.tools/voxelibre/mods/ENTITIES/mobs_mc/models/`, read-only; they are .b3d, so use them only to compare sizes).

## Interfaces / invariants
- **`tools/gen_standins.py`** (python3 stdlib only; write the glTF JSON and the binary buffer by hand, with base64-embedded buffers in .gltf or a .glb container). It is deterministic and writes `mods/minemon/minemon_creatures/models/mm_<body_plan>.glb` for the 8 body plans: biped, quadruped, serpent, avian, blob, insect, fish, other.
  - Each model is made of boxes (Minecraft style) with a skeleton (root, body, head, plus legs, wings, tail or segments by plan) and ONE animation clip. Frame ranges:
    - stand 0–20 (subtle breathing);
    - walk 21–41;
    - run 42–52;
    - punch 53–63 (lunge or bite);
    - die 64–74 (fall over);
    - sit 75–85 (crouched: used for the "exhausted" state).

    Use 1 frame = 1 unit of time (check what Luanti expects for glTF keyframe times vs frame numbers; S-11 lists this as an open question, so resolve it by testing in the client via the screenshot harness).
  - Size: about 1 node tall at visual_size 1, with the feet at y = 0 (the origin at the ground).
  - UVs map each box onto a 32×32 texture layout shared by all plans: body region, head region with a face area, and limb region.
- **Textures:** `mods/minemon/minemon_creatures/textures/mm_type_<type>.png` for all 17 types, 32×32 PNG written with zlib (stdlib).
  - Base colour per type (fire is warm orange, water is blue, ghost is purple-black, and so on), with a darker shade for the back and a lighter belly.
  - Pixel noise for texture, and a face area with 2 eyes: white sclera, black pupil, and a glint. Ghost and dark types get glowing red or purple eyes for creepiness.
  - A second variant `mm_type_<type>_shiny.png` with a hue shift.
- Register the files in ASSETS_LICENSES.md as project-owned procedural art (CC0).

## Steps

2. **Visual check:** add `tests/screenshot/creature_lineup.json` and a tiny test-only mod `tests/screenshot/minemon_lineup/`. It spawns static display entities (not mobs) of each body plan with 4 different type textures in a row near the camera, playing the stand animation. Run `bash scripts/screenshot.sh tests/screenshot/creature_lineup.json builds/shots_lineup`, extending the screenshot helper only if it cannot load an extra test mod; minimal changes. Look at the PNGs with the Read tool, and iterate on proportions, eyes and colours until they look good and readable at 5–10 m. Then also capture the walk and die frames.
